# Автоматизация сети ресторанов «Ромашка»

Учебный проект по курсу «Шаблоны проектирования». Выполняется в течение семестра: 
проект развивается постепенно, а применяемые паттерны проектирования фиксируются по мере появления.

- **Автор:** Артём Шишкин
- **Курс:** Шаблоны проектирования
- **Статус:** в разработке

## О проекте

Программное обеспечение для автоматизации сети ресторанов `ООО Ромашка` (10 ресторанов, 
производственный цех, централизованные закупки). Система должна охватывать:

1. Складской учет продукции
2. Производственный учет
3. Сопровождение курьерской службы
4. Финансовый учет и взаиморасчеты
5. Учет персонала
6. Оперативный контроль

Полный текст требований: [`Docs/TechnicalTask.md`](Docs/TechnicalTask.md).

## Стек

- Python ≥ 3.12
- [uv](https://docs.astral.sh/uv/) — управление окружением и зависимостями
- [ruff](https://docs.astral.sh/ruff/) — линтер и форматирование
- [basedpyright](https://docs.basedpyright.com/) — проверка типов

По ТЗ в дальнейшем планируются: SQLite, Swagger, HTML/JavaScript.

## Быстрый старт

## Структура проекта

| Каталог      | Назначение                                                        |
|--------------|-------------------------------------------------------------------|
| `Src/`       | Исходные коды приложения, точка входа — `Src/main.py`             |
| `Src/Core/`  | Общие классы, константы, перечисления                             |
| `Src/Logics/`| Бизнес-логика                                                     |
| `Src/Models/`| Доменные модели                                                   |
| `Src/Dtos/`  | DTO-модели для передачи данных                                    |
| `Tst/`       | Тесты (юнит, интеграционные, функциональные) — *будет добавлен*   |
| `Docs/`      | Документация: ТЗ, требования к коду                               |

Архитектура строится по принципам чистой архитектуры.

## Соглашения по коду

Подробно: [`Docs/CodeCases.md`](Docs/CodeCases.md). Кратко:

- каталоги — `CamelCase`, классы, свойства и методы — `lowercase_separated_by_underscores`;
- имена на английском, с использованием корректных доменных терминов;
- обязательные комментарии/докстринги для каждого класса, метода и свойства;
- принципы SOLID, KISS, DRY, YAGNI;
- тесты именуются по схеме `ОжиданиеРезультата_НаименованиеМетода_КраткоеОписание`.
